# 知命：模型选择与生成流程调整方案

核对日期：2026-09-25。状态：双任务方案已实现；模型横向盲评仍待具备其他供应商密钥后开展。已保留时辰范围、星座交界及详细大运流年规则。

实施记录：默认 `READING_MODE=parallel`，服务端固定并发两项任务，任务级 JSON 校验及整轮一次局部修复，SSE 协议 `reading-stream.v2` 逐块交付；`READING_MODE=single` 保留旧单次流程供回退和对照。模型仍为 DeepSeek 官方 `deepseek-flash`，`reasoning_effort=max`。本地 36 项测试、类型检查、生产构建通过；一次合成样本的真实联调中人格块约 30 秒交付，流年块首轮未过校验、经一次修复约 97 秒交付。该单例不能代表平均延迟或优劣。未接入千问，没有其密钥和对照结果。

## 1. 决策

继续使用 DeepSeek 官方 `deepseek-flash`，不因通用排行榜或其他产品的单张截图直接换模型。现有问题已证实涉及后端事实不足、模块禁用条件、过短的输出合同，不等于模型能力不足。上一轮实测已经能生成完整详细报告，但只有单个成功样本，不能据此断言与其他模型效果相同。

推荐先试验“两项固定任务并行、各自校验、逐块展示、失败局部修复”。不引入自治多智能体、角色辩论、规划器、工具循环、自动联网或 Agent 框架。并行主要改善首块正文的等待体验，不保证总耗时减半，也不保证质量自动提升。

大运与三个流年由同一任务共同分析，保留跨年比较及交运前后的连贯性。不要按事业、感情、财务或每个年份再各开一个 Agent。

## 3. 建议工作流

```text
用户提交 → 确定性排盘 → 立即显示人格类型、四柱、星座交界、大运阶段
                    ├─ 任务 A：人格正文、人格卡短句、轻量星座文化解读
                    │          → 模块校验 → 显示 A
                    └─ 任务 B：大运 + 上一/当前/下一流年 + 阶段总览
                               → 模块校验 → 显示 B
存在可修复错误 → 只修复失败模块一次 → 再校验 → 保留成功部分
```

同一份服务端 `ChartFacts` 是两个任务的唯一事实来源。两任务共享排盘指纹、规则版本和参考时刻，不各自重新排盘，不互相传递原始思考。

任务 A 只读本命、人格、星座及相关限制，不能评价当前大运或某年吉凶。任务 B 读取本命、当前及年度相交大运、十神藏干与合冲事实、三年范围和限制；不改写人格类型，也不写太阳星座。将原有 overview 移到 B，作为阶段总览，前端标签也相应调整，避免 A/B 分别概括人生而冲突。

正常完整报告 2 次调用；没有某任务的可用主题就跳过。每轮最多追加 1 次修复调用，总调用数不超过 3，并发最多 2。两个任务均失败时，只修复优先级更高的 B，A 提示未完成；不通过嵌套 SDK 自动重试突破总预算。

首个版本默认两个任务均保留现有 `reasoning_effort=max`，遵守用户先前指定最高思考档位。另设离线实验：A 对比 low/high/max，B 对比 high/max。只有相同样本质量不下降、延迟有明确收益，才提议修改生产默认值，不静默降档。

不先增加“分析 → 写作 → 审稿”三次串行调用。当前计算层已经负责事实；额外分析层可能重复消耗推理 token。确有“事实准确但报告空泛”的稳定缺陷时，再将两阶段分析写作作为独立实验，不直接全量上线。

## 4. 计算与内容边界

后端继续负责：农公历、历史时区、四柱、太阳星座交接、日主、人格式样、大运顺逆与阶段、流年区间、十神藏干及已支持的关系。模型只解释已计算事实。

现有时辰范围内阶段一致即可解读的规则必须保留。真的跨界时列候选及具体原因；调用更强模型或多个模型不能补出用户未提供的出生分钟。

大运约 400–650 字；每个允许解读流年约 500–800 字。内容目标包括依据、阶段主题、机会与代价、事业学习、人际关系、财务习惯及行动建议，不能靠重复免责声明或泛泛建议凑字数。

补充年度角色 previous/current/next：上一年使用回顾问题，不能声称知道用户过去经历，也不能把上一年写成即将发生；当前年建议需适用于当前时点；下一年写准备方向。各年度使用自己的大运阶段，不套用当前大运。

目前尚无旺衰、格局、喜用神判定引擎。需要这些内容时，先确定采用的流派、条件和不确定性，再由熟悉该体系的人复核参考样例及测试；不能让模型无依据新增“火一定是喜用神”。多个模型投票也不能作为正确性依据。

## 5. 校验与修复

保留严格 JSON、模块必需字段、年份及阶段编号、授权事实引用、身份标签、未授权技术结论与表达边界检查。本文不声称简单关键词或 fact ID 校验能证明整段自然语言语义正确；这部分需离线人工盲评。

正常段落的推荐字数作为质量目标；略少于目标不触发整份重写。空段落、缺失核心模块、异常超长响应依然拒绝。缺乏依据或矛盾是高优先级错误，少几个字不是。

修复输入只包含：失败任务、具体字段路径、原始许可事实、失败段落和明确错误。失败段落是不可信数据，不得被当作新指令。输出该模块的完整合法替换对象，不让模型返回任意代码补丁或任意 JSON 路径。成功模块不可被覆盖。

不默认增加一个审稿模型。可离线抽样检查无依据结论和跨年矛盾；若有稳定收益，再考虑有限抽样上线。使用另一个模型复核也不保证独立正确。

## 6. 前端等待和错误体验

排盘成功立即展示真实计算结果，不等模型写完。两个任务各自显示“正在解读人格”“正在分析大运流年”；完成并校验一个就显示一个。不得先展示未校验文本，再在结束时偷偷更改关键结论。

保留用户需要的动态反馈，优先呈现实际事件和已核实依据，如“已确认时辰范围内大运阶段一致”“已整理 2026 年与原局的关系”。不用定时器伪造已完成步骤、百分比或所谓多个大师讨论。

模型思考显示若继续保留，应按任务区分、标注生成中、限制长度；不得将它当作已校验结论或写入分享报告。取消任一整轮请求需终止所有未完成调用，保留已完成模块；不能因取消、前端重连或切换年份自动重复付费调用。

三个年份由 B 一次生成，切换年份无需新请求。一块失败只提示那块，允许明确点击重试；用户编辑出生信息后旧请求的任何结果都不得覆盖新报告。

服务端每轮共享 300 秒总截止时间，修复只使用剩余额度。展示首块时间是测量指标，不承诺 max 模式在固定数秒内完成。

## 7. 对照试验与换模型门槛

先用脱敏或合成的 40–60 组样本试验流程，不用本人的单一命盘调优。覆盖十种日主、不同排运性别、精确时间/时辰/未知、农历闰月、夏令时、节气/星座交界、起运前、交运年与跨年阶段。同一配置每组至少 2 次，评估稳定性。

第一轮：同一 DeepSeek 的现有单次流程 vs 两任务并行流程，保持事实与内容目标相同。第二轮：在胜出流程上比较 DeepSeek 与 Qwen Plus；必要时少量测试 Qwen Max。参数名称与能力按供应商适配，不把 DeepSeek 的 max 原样传给其他 API。

记录：事实错误、无依据技术判断、年份/阶段串用、正文重复、盲评可读性、首块正文 p50/p95、完整结果 p50/p95、首轮通过率、失败/修复率、每份成功报告总费用。不得把字数或“说中了”的主观反馈当成事实准确率。

建议门槛（产品决策标准，不是现有测试结果）：候选模型在两批独立样本中均获至少 60% 的盲选偏好，且事实错误率不升、费用和等待时间可接受，才考虑换；否则保留现模型。如果只改善文风，可只替换 A，不迁移 B。

新增供应商密钥由部署者以服务端环境变量配置；未配置就跳过候选测试，不借用其他应用凭据，不静默切换供应商发送用户数据。不将出生信息或 API key 放进评测日志；普通日志只记耗时、用量、版本及错误类别。

## 8. 最小实现改动与验收

1. `lib/server/reading-context.ts`：按 A/B 裁剪事实；增加年度角色和共有语境版本。
2. `prompts/system-prompt.ts`：拆分任务职责；维护原有事实边界，增加明确 JSON 合同和局部修复提示词。
3. `lib/server/reading-run.ts`：固定两任务并行、按模块校验与产出、共享超时及调用预算；保留单次模式供对照和回退。
4. `lib/server/reading-validate.ts` 与共享类型：增加任务级验证和结果状态，最终组合报告保持可复制、可保存。需要协议升级时同步前后端，不能混用 v1/v2。
5. `app/api/reading/route.ts`：SSE 增加 taskId/moduleId、模块状态和模块结果；全局序号单调递增，requestId/chartFingerprint 校验继续保留；每轮只发送一次结束事件。
6. `components/FateApp.tsx`、`ThinkingPanel.tsx`：逐块呈现，独立错误与重试；切换年份不调用模型；复制功能清楚标识未完成部分。
7. `lib/server/deepseek.ts`：默认模型与 max 不变。先只给离线评测增加明确的供应商适配，不建设通用 Agent 平台，也不急于增加数据库、队列或长期缓存。
8. 增加必要测试：A 先完成/B 先完成；一块失败另一块保留；一次修复预算；取消/超时传播；编辑信息隔离旧结果；重复点击去重；缺失事实降级；交运年阶段不串用；年份切换不增加调用。
9. 先跑现有测试、类型检查、构建，再做一次真实 DeepSeek 双任务联调；对比旧流程的用量与等待时间。没有候选模型密钥时应报告未测，不编排名。

实施中禁止 git add、git commit、git push、git merge、git rebase、创建标签或 PR。只修改并验证，保持改动未暂存。
