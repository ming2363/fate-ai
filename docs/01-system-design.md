# Fate AI：系统设计与实施方案

版本：1.2；日期：2026-09-24。本文是初始需求基线；网站已实现。当前双任务生成流程以 [04-model-and-generation-plan.md](04-model-and-generation-plan.md) 的实施记录为准，下面的单次 SSE 事件表仅对应 `READING_MODE=single` 回退路径。

配套文件：[编码总提示词](02-implementation-prompt.md)、[运行时解读提示词](03-runtime-prompts.md)。三份文件应一起交给实施方。

## 1. 产品目标与首版范围

做一个简体中文、手机优先、免登录的单页网站。用户打开链接，输入出生信息，获得容易理解的八字解读、中式人格卡、当前大运、年度流年和按出生时刻确定的太阳星座。

首版完成以下闭环：

1. 填写出生日期、出生时间、排盘性别、出生城市或时区。
2. 程序先返回排盘事实、日主人格标签、国风称号和太阳星座。
3. AI 基于程序提供的事实生成白话解读，等待时实时展示模型返回的思考文本。
4. 同页查看当前大运，切换上一／当前／下一流年。
5. 修改出生信息、重试解读、复制结果、保存人格卡图片。

页面只设一个主路由。会员、支付、聊天、合婚、每日推送、后台管理、上升星座、月亮星座、宫位和完整西方星盘不在首版范围内。

“中式 MBTI”是产品内的趣味称呼，实际分类为十天干日主＋性别，不做标准 MBTI 测评，也不把生日标签表达为经过心理测量的结论。页面直接呈现结果，不展示这段适用范围说明。

## 2. 已确定的默认口径

| 项目 | 首版决定 |
|---|---|
| 视觉 | 简约新中式：米白、墨色、朱红，少量五行配色 |
| 解读模型 | DeepSeek 官方 DeepSeek-V4.1-Flash；API 模型 ID 为 `deepseek-flash` |
| 思考模式 | `thinking.type=enabled`、`reasoning_effort=max`；首次与重试均保持最高档位 |
| 站点名称 | 暂用“知命”；标题文案集中配置，开发期间不因命名阻塞 |
| 人格分类 | 甲、乙、丙、丁、戊、己、庚、辛、壬、癸，共 10 种日主；男女组合为 20 个标签 |
| 国风称号 | 按日主固定映射，不由模型随机起名，不随年份变化 |
| 太阳星座 | 地心、热带黄道十二星座，以实际入宫时刻划分 |
| 出生时刻 | 按出生地当年的 IANA 时区规则还原 UTC，处理历史夏令时 |
| 八字时钟 | 将 UTC 换算为固定 UTC+08:00 的北京时间标准时再排盘；首版不启用真太阳时 |
| 八字年／月 | 年按立春交接，月按十二“节”的交接时刻 |
| 八字换日 | 采用 lunar 的 EightChar sect=2：晚子时日柱仍属当天，时柱按该流派处理 |
| 起运 | 采用 EightChar.getYun(gender, 2)，与换日 sect 分开配置和记录 |
| 流年范围 | 每个流年从当年立春起，到下一年立春前结束 |
| 出生日期范围 | 首版允许公历 1900-01-01 至提交时刻；底层节气数据必须覆盖首尾相邻年份 |

北京时间排盘是本产品选择的统一规则，并不声称是所有流派唯一正确的规则。结果的“排盘说明”需同时展示出生地当地时间、换算后的北京时间以及所用流派。国外出生或历史夏令时日期尤其不能静默套用当前北京时间。

西方太阳星座直接使用出生瞬间的 UTC；不得套用真太阳时、八字日柱换日规则或浏览器所在时区。热带黄道十二宫与天文学实际星座边界也不是同一个概念。[热带黄道定义](https://www.astro.com/astrowiki/en/Tropical_Zodiac)

## 3. 单页体验

### 3.1 输入区

主标题：“识得自己的底色，看清当下的节奏。”

辅助文案：“一份八字解读，一张中式人格卡。”

| 字段 | 交互和验证 |
|---|---|
| 出生日期 | 默认公历；支持农历切换及闰月；拒绝无效日期、无效闰月及未来出生时间 |
| 出生时间 | “知道具体时间／只知道时辰／不清楚”；具体时间默认 HH:mm，交界情况下可补充秒 |
| 排盘性别 | 男／女；说明用于传统排运；不用于推断性取向或套用性别刻板印象 |
| 出生地点 | 常用城市选择，展示对应 IANA 时区；未找到城市可手动选择出生时区 |
| 关注方向 | 选填：综合、事业、感情、财运；默认综合 |
| 具体困惑 | 选填，最多 200 字；作为待分析文本，不作为系统指令 |

不收集姓名、电话、证件或精确住址，不自动索取设备定位。时区必须由出生地点映射或用户明确选择，不能直接使用访问者当前所在时区。

时辰选项使用当前所选民用日期内的区间。为避免“子时到底是哪一天”歧义，拆成“早子时 00:00–00:59”和“晚子时 23:00–23:59”；其余按丑时 01:00–02:59 至亥时 21:00–22:59。内部统一使用左闭右开区间。

### 3.2 结果顺序

1. **中式人格卡**：如“辛金女 · 珠玉含光”；显示日主、五行、三个关键词、太阳星座徽标。
2. **一句话总览**：80–120 字，概括性格表达、当前阶段和流年重点。
3. **人格解读**：优势、容易卡住的地方、相处建议。
4. **当前大运**：起止范围、阶段主题、可关注方向、提醒；前后大运可展开。
5. **年度流年**：上一／当前／下一流年，分事业、感情、财务节奏，附两条行动建议。
6. **排盘依据**：折叠展示四柱、日主来源、起运口径、时区换算、星座交界依据。
7. **操作**：修改信息、复制解读、保存人格卡。

大运正文约 400–650 字，每个可解读流年约 500–800 字，分主题与依据、机会、提醒、生活领域及行动建议。只有选中的流年展开正文；十神与合冲依据按需展开。术语首次出现时用一句短句解释。手机端纵向阅读，不要求横向拖动时间轴。

### 3.3 必须具备的状态

- 初始、字段错误、排盘中、排盘完成且 AI 生成中、完整结果。
- 信息不足的简版结果、星座或日主待确认、AI 失败但排盘已完成。
- 排盘计算失败、网络中断、限流、导出失败。

失败保留表单。排盘失败不展示伪造命盘；AI 失败保留人格基础卡和星座计算结果，并提供“重试解读”。加载文案反映真实阶段，不用虚构百分比或人为等待动画。

### 3.4 实时思考面板

排盘完成后先展示人格基础卡，在其下方放置轻量“AI 思考中”面板，包含已用时间、实时文本、“展开／收起”和“取消生成”。默认显示约 4 行，展开后在固定高度区域阅读；保持新中式留白，不做聊天窗口。

- 文本来自本次 DeepSeek 响应的 `reasoning_content`，不是预先写好的轮播话术。标注“过程内容可能调整，请以最终解读为准”；思考文本未经最终报告校验，不能覆盖程序事实或作为最终结论。
- 状态按真实事件推进：“等待模型响应”→收到思考后“AI 思考中”→收到正文后“正在整理解读”→服务端校验时“正在检查结果”。模型没有返回思考时可以直接进入正文阶段，不能补造思考。
- 尚未收到内容或长时间没有新片段时，显示“仍在等待模型返回”及持续计时；不显示假百分比，不推断模型正在分析哪个命理模块。网络心跳只能说明连接仍在，不能当作模型进度。
- 每约 100ms 合并一次界面更新；仅当用户原本在底部时自动跟随。默认仅保留最近 6000 个 Unicode 字符，达到上限提示“仅展示最近的思考内容”；不把几十万 token 全部堆进 DOM 或浏览器内存。
- 成功后面板自动收起，可在本页展开查看当前保留的片段。失败显示简短原因，保留基础卡并允许重试；自动重试时明确显示“正在重新生成”，清空上一轮临时文本并重新开始，整轮计时不重置。
- 取消、修改出生信息或离开页面时中止浏览器请求，并由服务端取消上游生成、释放资源。思考文本仅存当前页面内存，不写日志、持久化存储，不加入复制报告或 PNG。
- 展开和取消可用键盘操作；读屏只播报阶段变化，不逐字播报思考流；尊重减少动画设置。

## 4. 中式人格卡

### 4.1 分类和称号

日主来自排盘的日干，不是出生年的天干、纳音、生肖，也不是“五行里数量最多的那个”。以下名称和关键词是本产品的原创文案设计，不作为古籍原句或心理诊断。

| 日主 | 五行／意象 | 固定国风称号 | 基础关键词 |
|---|---|---|---|
| 甲 | 木／大树 | 苍松立岳 | 生长、担当、原则 |
| 乙 | 木／藤萝 | 青藤知风 | 灵活、细腻、韧性 |
| 丙 | 火／太阳 | 曜日明行 | 热情、表达、行动 |
| 丁 | 火／灯火 | 灯火映心 | 专注、体察、温度 |
| 戊 | 土／山岳 | 山岳守衡 | 稳重、承载、边界 |
| 己 | 土／田园 | 沃野藏秀 | 务实、照料、积累 |
| 庚 | 金／刀剑 | 砺锋开路 | 决断、执行、直接 |
| 辛 | 金／珠玉 | 珠玉含光 | 细致、审美、分寸 |
| 壬 | 水／江海 | 江海行舟 | 开阔、探索、应变 |
| 癸 | 水／雨露 | 清露知微 | 敏锐、观察、含蓄 |

类型标签例：“辛金女”“戊土男”。称号和基础关键词与性别无关。同类型的个性化正文可以结合其他已确定的命盘事实，但不得改变日主、称号，也不得因切换流年而改变人格类别。

日主存在多个候选时，卡片显示“日主待确认”，列出候选，不随机挑选一个。太阳星座不确定并不妨碍展示已确定的日主人格；各模块独立降级。

### 4.2 图片导出

人格卡本身是可访问的 HTML，导出为 PNG，文字和背景合成即可，不要求每次调用图像生成模型。首版可以按需加载 [html-to-image](https://github.com/bubkoo/html-to-image)；字体加载完毕后导出，避免中文字形缺失。图片资源使用同源或可正确跨域读取的来源。

默认图片只包含：日主标签、国风称号、关键词、已确定的星座或“星座待确认”、一条短句、站点名称和简短娱乐说明。不要包含生日、城市、精确时刻或私人困惑。页面和导出图使用同一份卡片数据。

## 5. 星座计算：按年份和出生时刻判断

### 5.1 计算定义

采用热带黄道太阳星座：以太阳地心视黄经每 30° 为一段。原则上，已知同一个准确瞬间，在所选体系下只属于一个星座；“同一天两种星座”是这一天内发生了入宫交接，不代表一个人自动同时拥有两个太阳星座。

出生地点在这里用于还原时区。相同 UTC 瞬间，不应因为城市不同而得到不同太阳星座。

推荐复用经过校验的节气时刻计算：十二“中气”的太阳黄经恰好落在 30° 边界，因此可以生成太阳入宫事件表。这里复用的是每年的天文时刻，不是传统固定日期表。其黄经对应关系可核对[香港天文台二十四节气资料](https://www.hko.gov.hk/tc/gts/time/24solarterms.htm)。

| 入宫太阳黄经 | 星座 | 对应中气 |
|---|---|---|
| 0° | 白羊座 | 春分 |
| 30° | 金牛座 | 谷雨 |
| 60° | 双子座 | 小满 |
| 90° | 巨蟹座 | 夏至 |
| 120° | 狮子座 | 大暑 |
| 150° | 处女座 | 处暑 |
| 180° | 天秤座 | 秋分 |
| 210° | 天蝎座 | 霜降 |
| 240° | 射手座 | 小雪 |
| 270° | 摩羯座 | 冬至 |
| 300° | 水瓶座 | 大寒 |
| 330° | 双鱼座 | 雨水 |

### 5.2 实现要求

1. 取得出生年份及前后年份的中气交接时刻，统一为 UTC 事件列表，按时刻排序并去重。
2. 每条事件记录 `signId`、`startUtc`、来源、引擎版本。跨年别名必须归一化，不能因为“冬至”和下一年冬至键名不同而漏算。
3. 相邻事件定义星座区间 `[startUtc, nextStartUtc)`。算法层恰好位于交接时刻属于新星座。
4. 将用户出生时刻或可能时间范围与事件区间比较，取得一个或多个候选星座。
5. 展示边界依据时，同时展示当地日期、当地时间、UTC 偏移和时区名称，避免只写一个无时区的“15:30”。

**禁止调用 lunar 的 `Solar.getXingZuo()`／`getXingzuo()` 得到最终星座。** 核查时该方法只比较月日，不能满足时刻交界要求。[相关源码](https://github.com/6tail/lunar-javascript/blob/master/lunar.js)

可复用公开节气表 API，但不要调用库的私有天文函数。核对锁定版本的节气输出时间基准：当前源码的精确节气按固定 UTC+08:00 给出，必须据此转 UTC；不能把它解释成服务器当地时间，也不能套用历史 Asia/Shanghai 夏令时。

### 5.3 时间不完整与精度

| 输入 | 计算表示 | 结果策略 |
|---|---|---|
| 知道秒 | 覆盖所填一秒的时间区间 | 唯一星座时确定；紧邻引擎边界仍需提示 |
| 知道分钟 | `[该分钟开始, 下一分钟开始)` | 不暗自认定出生秒数为 00 |
| 只知道时辰 | 对应民用时间区间，转换为可能 UTC 区间集合 | 覆盖入宫交接则返回两个候选 |
| 时间不详 | 出生地该民用日期的全部有效时间 | 全天属于同一星座才给唯一结果 |
| 时区不详 | 尚不能构造出生瞬间 | 要求补充时区，不猜测 |

夏令时转换日可能有 23／25 小时；“一天”不能写成固定的 24 小时 UTC。时区回拨的重复时刻提供两个可选偏移，跳时造成的不存在时刻返回字段错误，不静默移动一小时。时间处理建议使用 Temporal；其 `disambiguation`、`offset`、`overflow` 需显式设置。[Temporal 文档](https://tc39.es/proposal-temporal/docs/zoneddatetime.html)

边界事件是算法估计值，输出秒数不代表拥有一秒的天文精度。首版设定 `boundaryGuardSeconds=120` 为保守的产品缓冲区，候选计算将入宫边界视为 `[T-120s, T+120s]` 的不确定范围；这不是对引擎真实误差的承诺。输入范围与缓冲区相交时，返回 `near_boundary` 或 `ambiguous`，不显示伪造概率。缓冲值只有在独立精度验证后才可缩小。

上线门槛：用权威年历中可取得的带时刻数据、覆盖不同年代的独立天文样本校验入宫事件；首版验收目标为可比样本误差不超过 60 秒，并记录参考数据自身的舍入精度。不能仅拿同一库生成的数值作为预期结果。无法达到目标时，替换或修正节气事件来源，再上线时刻划分功能。

校验数据可从[香港天文台节气日期与时间](https://www.hko.gov.hk/tc/gts/astronomy/Solar_Term.htm)和[2026 年天文年历](https://www.hko.gov.hk/en/gts/astron2026/files/HKO_almanac_2026.pdf)开始；历史年代需补齐独立资料。日期表只有“某月某日”时，不能作为分钟精度证据。

文案示例（只描述形式，具体星座与时刻由实际计算填入）：

> 你的出生日期位于两个星座的交界日。目前提供的出生时间范围跨过交接时刻，可能是 A 或 B。补充更准确的时间后，可以进一步确认。

## 6. 八字、大运和流年

### 6.1 确定性计算

统一入口：当地出生信息 → UTC 时间范围 → 固定 UTC+08:00 排盘时间范围 → 四柱／日主／起运／大运／流年。

使用 `Solar.fromYmdHms` 传入显式年月日时分秒，不使用依赖进程本地时区的 `fromDate(new Date(...))`。农历先验证闰月并转换成公历日期标签，再与用户输入的当地钟表时间、出生时区组合；页面展示转换结果供用户检查。

程序负责四柱、日干、五行归属、十神等基础字段以及起运和运势时间区间。AI 负责传统文化语境下的解释。首版不声称已实现严格的旺衰、格局、从格、喜用神裁定；五行字数统计不等于五行强弱，不使用“缺什么就补什么”的自动规则。

年、月、日柱及流派说明以[八字 API 文档](https://6tail.cn/calendar/lunar.bazi.html)为依据。编写薄封装，锁定依赖和规则版本，不让模型自行选择流派。

### 6.2 时间范围不能压成一个代表时刻

出生时间不完整时，按范围内可能改变四柱的事件切分：时柱边界、日柱边界、立春和月节交接，再计算各段。只将各段一致的字段标为确定，变化的字段列为候选。太阳入宫、时区变化和引擎节气缓冲也要纳入各自模块的候选判断；不能仅采样中午一次。

分钟级输入可生成常规报告，但交界附近必须保留分歧。只知时辰时，覆盖整个时辰范围核对：四柱及当前大运阶段一致时可解读大运，年度内阶段序列一致时可解读对应流年；起运和交运日期保留范围，不输出伪精确时刻。实际跨界时提示具体分歧。全天未知仍只展示稳定的日主与星座及年度历法信息。不要用假定中午的起运结果驱动叙述。

已计算事实包括：各柱、当前大运及各年相交大运相对日主的十神与藏干；大运／流年与稳定原局的天干五合、地支六合、六冲及重复关系。不直接判定合化、旺衰或喜用神。详细解读引用事实 ID；大运分主线、机会、提醒，流年分年度概括、阶段、事业、人际、财务与两项行动。

### 6.3 大运

- 排盘性别参数按依赖库明确映射，禁止取反；记录顺排或逆排。
- 起运采用 `getYun(gender, 2)`；读取实际起运时刻，而不只是起运年份。
- 第一次大运起点为计算所得起运时刻；后续每运在统一的排盘时间口径下增加 10 个公历年。处理闰日时采用日期约束到该月最后有效日的规则。
- 通过时间区间判断当前大运，不仅比较 `getStartYear()`。交运当天的前后应属于不同阶段。
- 区分出生后尚未起运的阶段，不能把索引 0 的占位阶段当作正式第一步大运。
- 如出生时间精度会使当前是否交运产生分歧，返回候选，不给唯一阶段结论。
- 默认显示当前大运及前后各一运的简表；没有前一运时正常隐藏。

### 6.4 流年

- `liuNianYear=Y` 的区间为 `[Y 年立春, Y+1 年立春)`。
- “当前流年”由服务器当前时刻与立春比较决定，不能直接等于系统公历年份。元旦后但立春前仍属于上一流年。
- 流年干支由程序计算；不因生肖年按春节划分而改用春节。
- 一次报告包含当前流年前后各一年，点击切换不额外调用模型。
- 每个流年与实际大运区间求交集；如果一年内交运，报告注明前后阶段，不能全年套同一大运。
- 出生前的年份不生成个人经历或运势；年度区间与出生日期相交时从出生后开始解释。
- 年度内容分事业／学习、感情／人际、财务节奏，再给两条行动建议。模型不可把运势词语写成死亡、疾病、破产等确定预言，也不可给具体买卖资产指令。

## 7. 最小系统架构

采用“确定性排盘＋结构化 AI 解读”的两阶段流程。排盘先以 JSON 返回；AI 请求保持流式连接，实时传送思考片段，最终报告校验后一次返回。

推荐技术栈：Next.js＋TypeScript，一个 Node 服务同时提供页面与 API；普通 CSS 或项目已选的样式方案。通过 [Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers) 实现两个 POST 接口。日期层使用 `@js-temporal/polyfill`，中国历法使用 `lunar-javascript`，输入及模型输出使用 Zod 等一种验证工具。实际安装时核对官方 API 并锁定版本。

如果实施仓库已有稳定技术栈，保留现有栈，落实相同计算合同即可。无需引入微服务、数据库、向量库、知识库检索、任务队列或自定义 Agent 框架。

建议文件职责如下，不要求机械拆成大量类：

| 文件或目录 | 职责 |
|---|---|
| `app/page.tsx`、页面样式 | 表单、状态管理、结果展示、导出入口 |
| `app/api/chart/route.ts` | 校验输入，返回程序计算的事实 |
| `app/api/reading/route.ts` | 重算并校验事实，调用模型，验证解读 |
| `lib/birth-time.ts` | 日期、农历、时区、精度与 UTC 范围 |
| `lib/calendar.ts` | 排盘、节气事件、大运流年 |
| `lib/zodiac.ts` | 太阳入宫区间和候选星座 |
| `lib/persona.ts` | 十日主固定标签、国风称号、关键词 |
| `lib/reading.ts` | 精简上下文、模型流解析、思考转发、重试、结果验证 |
| `lib/contracts.ts` | 输入、事实和解读结构 |
| `data/cities.json` | 有来源的城市到 IANA 时区映射；没有匹配时手动选时区 |
| `prompts/` | 版本化运行时提示词 |

城市映射只需要时区，不需要地理定位 API 和用户精确坐标。不得由模型猜测城市的历史时区；历史偏移交给 IANA 时区数据库。

公共节气事件可按年份＋引擎版本放进有界内存缓存。不缓存跨用户的私人出生信息和解读。页面只在当前会话内保存当前报告。

## 8. 接口与数据合同

### 8.1 请求

`POST /api/chart` 和 `POST /api/reading` 接受同一份出生输入；后者多接收 `requestId`、`focus` 和可选 `question`。服务端再次排盘，不信任浏览器提交的命盘或星座结论。这样避免为两次请求引入命盘签名存储。

请求示例只表示字段格式，不代表示例生日对应某个已验证命盘：

```json
{
  "requestId": "客户端生成的 UUID",
  "calendar": "solar",
  "birthDate": { "year": 1995, "month": 8, "day": 23, "isLeapMonth": false },
  "birthTime": { "precision": "minute", "value": "14:35", "shichen": null },
  "genderForCalculation": "female",
  "birthPlace": { "cityId": "cn-shanghai", "timeZone": "Asia/Shanghai", "offsetChoice": null },
  "focus": "general",
  "question": ""
}
```

`precision` 允许 `second | minute | shichen | unknown`；字段按判别联合校验，不接受冲突组合。`offsetChoice` 只有发生历史重复时间且用户明确选择时才接受，并验证其属于该时区该时刻的合法候选。完全在未来的出生范围拒绝；当前日期或当前分钟只有一部分已经过去时，取可能范围与提交时刻之前的交集，不能为尚未发生的时刻排盘。

服务端生成 `asOfUtc`，用于确定当前大运和流年；同一轮的 chart 与 reading 通过客户端回传 chart 的 `asOfUtc` 进行对齐，服务端只接受最近 5 分钟内的值，其余要求刷新。`asOfUtc` 不是用户任意查询的自由参数。

### 8.2 确定性事实

`ChartFacts` 至少包含：

| 字段 | 含义 |
|---|---|
| `schemaVersion`、`rulesVersion`、`engineVersion` | 数据合同、排盘口径和计算库版本 |
| `asOfUtc`、`chartFingerprint` | 本轮计算时刻与输入／规则／结果关联标识 |
| `birthUtcRanges` | 可能出生 UTC 范围列表，每段左闭右开 |
| `timeBasis` | 出生时区、历史偏移、UTC+08:00 排盘口径、输入精度 |
| `bazi` | 四柱确定值或候选、日主、各模块状态 |
| `persona` | 确定标签、称号、关键词；不确定时相应值为 null 并列候选 |
| `zodiac` | 体系、状态、唯一星座或候选、交界事件、缓冲范围和来源 |
| `luck` | 是否起运、起运精度、当前及前后大运、交运区间或候选 |
| `annuals` | 上一／当前／下一流年的精确区间、干支及相交大运阶段 |
| `factCatalog` | 供模型引用的白名单事实集合，每条有稳定 `id` 与中文说明 |
| `allowedTopics`、`limitations` | 可解读模块及程序生成的不确定性提示 |

每个模块独立使用 `determined | ambiguous | unavailable`；星座另带 `nearBoundary` 布尔值。`determined` 表示在规定输入精度和计算规则下唯一，不表示占卜预测经过科学验证。

`chartFingerprint` 由规范化出生输入、计算规则版本和 `asOfUtc` 生成，不包含模型文案；关注方向和用户困惑属于另一个请求体指纹。它是关联标识，不是访问凭据，不放到 URL 和公共日志；不得将出生日期哈希称为匿名化。服务端只在内存中使用，不把它作为可枚举的公共查询接口。

### 8.3 解读流与最终结果

`/api/chart` 返回普通 JSON；`POST /api/reading` 返回 `text/event-stream; charset=utf-8`。浏览器用 `fetch` 的 POST 请求与 `ReadableStream` 接收 SSE，不使用仅支持 GET 的原生 EventSource，不把出生信息放进 URL。不增加 WebSocket、轮询接口或后台任务系统。

每个事件按 SSE 的 `event: 名称`、`data: 单行 JSON`、空行编码。所有数据事件包含 `requestId`、`chartFingerprint`、`attempt`（1 或 2）、`seq`（整轮单调递增）；其余字段如下：

| 事件 | 额外字段与行为 |
|---|---|
| `status` | `phase: waiting \| thinking \| answering \| validating`，只反映真实已发生阶段 |
| `thinking_delta` | `text`：本次新增思考片段，前端以纯文本追加 |
| `retry` | `message`：安全的简短原因；attempt 增加，前端清空旧临时文本 |
| `result` | `readingStatus: generated \| partial`、`reading`：通过全部校验的 `reading.v1` 对象 |
| `error` | `readingStatus: failed`、`reading: null`、`code`、`message`、`retryable`；不回传上游原始错误正文 |
| `done` | `outcome: success \| failed`，正常连接的终止标记 |

成功顺序为 `result → done`，不可恢复失败为 `error → done`，二者互斥。可恢复故障先发 `retry`，不先发终止错误。每轮最多一个 result 或终止 error；收到 done 后关闭连接。无 result 就不能展示成功；没有 done 的意外 EOF 提示连接中断，不能自动重发付费请求。用户主动断开时可能无法发送终止事件，但仍必须清理资源。

所有事件只作用于匹配当前 `requestId`、`chartFingerprint` 和本地请求序号的界面；忽略已处理的 seq。编辑表单或重新提交会取消旧请求、递增序号；旧片段即使晚到也不能覆盖新结果。首版不做断点续传，手动重试使用新 requestId。

发出流响应头之前：输入错误用 422 并给字段路径；限流用 429 和 Retry-After；重复进行中的请求用 409；计算不可用用 503，均返回普通 JSON 错误。流开始后不能再更改 HTTP 状态，统一通过 error 事件告知超时等失败，前端保留 `/api/chart` 的成功数据。

响应设置 `Cache-Control: no-store, no-transform`；部署时关闭代理缓冲，适用时加 `X-Accel-Buffering: no`，确保片段实际及时到达浏览器。每约 15 秒可以发送 SSE 注释心跳，不计作思考内容，也不延长整轮截止时间。

## 9. AI、隐私和失败恢复

模型只能写解读正文，不能决定日主、性别标签、国风称号、星座、四柱、交接时刻和年份。服务端传给模型的上下文包括结构化事实、允许主题、时间不确定性和用户选填困惑；不需要把原始完整生日、地点和精确出生时刻传给模型。

### 9.1 DeepSeek 官方接入配置

用户指定 DeepSeek 官方 DeepSeek-V4.1-Flash，固定使用官方 API，不经过第三方中转。根据 2026-09-24 核对的[官方发布说明](https://api-docs.deepseek.com/news/news260910/)，该模型的调用 ID 是 `deepseek-flash`，不是自行拼写的 `deepseek-v4.1-flash`。该 ID 是服务别名，部署时需再次核对其对应版本；不得静默更换模型或供应商。

| 配置 | 值 |
|---|---|
| API Base URL | `https://api.deepseek.com` |
| 请求地址 | `POST https://api.deepseek.com/chat/completions` |
| 鉴权 | `Authorization: Bearer ${DEEPSEEK_API_KEY}`，只在服务端组装 |
| model | `deepseek-flash` |
| thinking | `{ "type": "enabled" }` |
| reasoning_effort | `max`，最高思考档位；不能用默认的 `high` 替代 |
| response_format | `{ "type": "json_object" }` |
| max_tokens | 首版显式使用 `131072`，与官方最高思考档位当前默认总生成上限对齐 |
| stream | `true`；服务端解析上游 SSE，向前端发送第 8.3 节的事件 |
| stream_options | `{ "include_usage": true }`，读取最终用量；中断时用量可能不可得 |
| temperature / top_p | 首版省略，采用官方默认采样设置 |
| 请求总超时 | `DEEPSEEK_TIMEOUT_MS=300000`，即整轮解读含重试最多 300 秒 |

调用参数依据：[官方快速开始](https://api-docs.deepseek.com/quick_start/)、[Chat Completions 参数](https://api-docs.deepseek.com/api/create-chat-completion/)、[思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。最高思考档位与输出 token 上限是两个参数；不能只增大 `max_tokens` 却漏设 `reasoning_effort=max`。131072 是生成预算上限，不是要求模型把报告写长，也不保证每次都消耗这些 token；正文长度仍受产品输出合同约束。

DeepSeek 此接口提供 JSON Output，不等于服务端严格 JSON Schema 约束。使用 `json_object`，在提示词中明确 JSON 格式和字段结构，再用后端 Schema 校验。不要传未经官方支持的 `response_format.type=json_schema`，也不要为了强制工具输出而关闭思考模式。思考模式下 `temperature` 不生效，删除原方案“降低温度保证稳定”的建议；人格稳定依靠程序固定映射。

分别处理 `choices[0].delta.reasoning_content` 和 `choices[0].delta.content`：前者转为 thinking_delta 发给当前请求用户；后者只在服务端累积成最终 JSON，禁止把两者拼在一起。两个字段可能同时出现，必须分别判断，不能用互斥的 if/else。思考文本不加入日志或下一次重试，不作为模型指令执行。

上游 SSE 解析必须支持任意网络分块、跨块 UTF-8 中文、换行分隔、注释心跳、空／null 字段和结束元数据。等待正常 `finish_reason=stop`、`[DONE]` 及 JSON／Schema 校验通过后才发送 result；`length`、中断、空正文或其他异常结束都不能标为成功。正文累积设置 256 KiB 上限，超过即取消并报错；思考按片段转发，不在服务端无限累积。响应流解析可复用已有工具，不能假设一次网络 chunk 就是一个完整 JSON 事件。

服务端环境变量示例保存在项目根目录 `.env.example`；实际密钥单独存于本地 `.env.local`（权限 0600），并由 `.gitignore` 排除。分享本文和提示词时只分享变量名及示例配置，不附带真实密钥；部署到其他机器时，通过部署平台的服务端密钥配置注入。禁止 `NEXT_PUBLIC_DEEPSEEK_API_KEY`、前端直连或在模型提示词里放密钥。

最高思考档位可能增加等待时间。页面先显示基础卡，再按第 3.4 节实时展示思考；流式输出改善等待体验，不承诺缩短模型计算时间。300 秒是整轮总时限，不因收到片段、心跳或重试而重置。Node 服务、反向代理和浏览器请求时限须覆盖此预算并留出传输余量；宿主平台不支持该时长时，选择支持长请求的部署方式，不得静默降低思考档位。

### 9.2 校验、恢复与数据保护

- 使用 JSON Output 生成 JSON，由服务端 Schema 校验未知字段、字数、数组长度、事实引用、年份与阶段引用。
- 用户困惑作为独立不可信数据字段，不能覆盖 system prompt；禁止模型调用工具或访问外部 URL。
- 每次解读最多两次模型调用，整轮共用 300 秒截止时间。第一次的可重试临时故障或结构校验失败，且仍有剩余时间时，才允许一次重试；SDK 内置重试应关闭或纳入相同总次数。两次都使用 `deepseek-flash` 和 `reasoning_effort=max`。鉴权／参数错误、用户取消、达到总超时或 token 上限时不自动反复请求；不得通过换模型、关闭思考或降低档位兜底。
- 基于依据引用只能确认输出引用了有效事实，不能自动证明语义正确；边界样本与文案需人工审阅。
- API 不返回未经校验的半段解读 JSON；实时思考仅作为独立的临时文本展示，使用文本节点渲染，不执行 HTML、链接或代码。失败不使用假 AI 内容冒充成功；基础卡可继续由固定模板展示。
- 前端禁止重复提交；后端同一短期匿名会话＋requestId 的进行中重复请求返回 409 `REQUEST_IN_PROGRESS`，ID 与请求体指纹不一致返回 409 `REQUEST_ID_CONFLICT`，都不再次调用模型。仅保存进行中标记，结束或取消后删除，不复用同一个可读流、不引入广播缓存。匿名会话使用服务端生成的随机会话 cookie（HttpOnly、SameSite=Lax，生产环境 Secure，短期有效），无需账户或会话数据库，不能单靠客户端 cookie 绕过 IP 限流。
- 首版单 Node 实例可使用有界内存限流，默认每来源 IP 每 10 分钟 5 次 AI 解读；只信任部署平台明确提供的代理 IP。多实例部署前将限流交给共享网关或平台能力。
- 进程重启会重置内存额度，模型供应商的预算上限应另外配置。不要以一个进程内计数器承诺全站每日硬上限。
- 日志只记录随机 requestId、阶段耗时、模型耗时／token 用量、规则版本、错误码及确定／不确定数量；不记录出生信息、用户困惑、模型完整上下文和正文。
- 两个 POST 接口使用同源策略和请求体大小限制，响应 `Cache-Control: no-store`；检查部署环境的请求日志和错误追踪也没有自动采集正文。

| 正文 | 系统中文黑体，移动端至少 16px，行高约 1.7 |

具体颜色组合开发时验证可读对比度。五行颜色旁始终保留文字名称。按钮触控区域至少约 44px，键盘焦点清楚，输入框具有可见标签，错误提示与输入关联，动态结果有适度的可访问播报。尊重减少动画设置。

不做大面积动态星空、复杂卷轴动画或占满首屏的宣传区。表单在首屏即可触达。星座作为人格卡上的次级徽标，八字和中式人格维持主视觉。

## 11. 实施顺序与完成标准

| 阶段 | 交付内容 | 通过标准 |
|---|---|---|
| 1. 合同与时间层 | 输入结构、时区换算、精度区间、农历转换、规则版本 | 非法日期拒绝；夏令时、跨日和未知时间处理正确 |
| 2. 确定性计算 | 节气事件、日主、人格映射、大运流年、太阳星座 | 完成独立历法样本校验；固定日期星座 API 未被用于判定 |
| 3. 单页体验 | 表单、基础结果、人格卡、年份切换、折叠详情 | 手机与桌面可用；未知状态清楚；旧请求不覆盖新报告 |
| 4. AI 解读 | 流式思考、运行时 prompts、结构化输出、引用检查、超时和重试 | 正常／失败／恶意用户文本可运行；取消能中止上游生成 |
| 5. 导出与运行准备 | PNG、复制、限流、日志脱敏、环境变量、README | 导出不带出生信息；无密钥也可排盘并明确提示 AI 未配置 |

实施方必须留下并运行一组精简但有效的检查，重点验证下面这些实际风险：

1. 十二个入宫事件的前后、算法层恰好交界点、公众结果的边界缓冲；分钟和时辰范围跨界。
2. 同一出生当地日期内，交界前后得到不同星座；时间未知时返回候选，不返回“双重星座人格”。
3. 相同 UTC 瞬间以不同时区输入，太阳星座相同；切换进程 TZ 不改变结果。
4. 时区回拨重复时刻、跳时不存在时刻、23／25 小时民用日期，以及历史中国夏令时样本。
5. 公历闰日、农历闰月、无效日期；不要让库将非法日期自动进位后当作有效生日。
6. 立春和月节前后，23:00 与 00:00 换日口径；时辰的早子／晚子选择不跨错日期。
7. 甲乙丙丁戊己庚辛壬癸十类型、男女标签、称号；日主来源为日干，跨流年标签保持不变。
8. 起运前、真实交运时刻前后、某流年内交运；缺时辰时不生成确定起运日期。
9. 元旦至立春的“当前流年”；新生儿不生成出生前的个人经历。
10. AI 输出非法 JSON、未知事实 ID、错误年份、提示词注入、超时与重试上限；缺密钥保留基础卡。确认请求使用 DeepSeek 官方地址、`deepseek-flash`、思考 enabled、effort max；解析最终 content 而不是 reasoning_content，截断输出不得成功。
11. 快速连续修改输入；失败后重试；PNG 的中文、隐私字段和移动端内容完整性。
12. 用模拟上游流覆盖中文跨网络块、同一片段含思考和正文、无思考直接正文、长时间无片段、异常结束／缺少 done、第二次尝试清空旧思考；确认最终报告只来自验证过的 content。
13. 取消和断开能释放上游连接与进行中标记；重复请求不重复调用模型；思考文本滚动和 6000 字上限、正文缓冲上限、键盘／读屏、实际部署代理不缓冲。模拟流明确用于测试，不能当作真实模型结果展示。

程序内部的比较逻辑可以用可控的合成事件测试；天文准确性还必须使用不同来源的真实样本验证。两种检查不能互相替代。校验记录保存来源、年份、时区、参考精度、实际差值和计算库版本。
