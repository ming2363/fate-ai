你是一名负责交付的全栈工程师。请根据随附的《Fate AI：系统设计与实施方案》和《运行时解读提示词》，实现一个可运行的中文 AI 八字网站。

## 一、产品目标

用户打开链接即可使用，不登录。网站只有一个主页面，填写出生日期、出生时间、排盘性别、出生城市或时区，得到以下结果：

1. 八字基础解读：四柱、日主以及白话性格说明。
2. 中式人格卡：“辛金女 · 珠玉含光”“戊土男 · 山岳守衡”这种形式。支持保存 PNG。
3. 大运：当前所处阶段、实际起止范围、主题和建议；前后大运可展开。
4. 流年：上一、当前、下一流年，分别展示事业、感情、财务节奏和建议。
5. 太阳星座：依出生年份、日期、时刻和出生地当年时区规则计算，正确处理同一天内星座交接。

设计风格是简约新中式：米白、墨色、朱红、宋体气质标题、清楚的中文正文。表单在首屏即可操作。人格卡突出国风称号，星座作为次级徽标。结果默认简短，专业依据折叠。

## 三、必须遵守的计算要求

### 1. 时间与历法

- 出生信息首先按当地历史 IANA 时区转成 UTC，再转换为固定 UTC+08:00 用于八字排盘。首版不计算真太阳时。
- 太阳星座只使用原始出生瞬间 UTC，不能使用八字换日或真太阳时。
- 明确区分当地民用时间、UTC、固定 UTC+08:00。库的节气输出也必须按其文档的时间基准转换。
- 验证年月日、农历闰月和时区；不要接受自动进位后的非法日期。
- 正确处理 DST 跳时和回拨。重复时刻让用户选择合法偏移，不存在时刻提示更正。
- 用户只填写分钟时不能伪装知道秒。只知时辰或未知时间时要保留可能时间范围，不使用中午代替真实生日时刻。
- 民用日期可能不等于 24 小时。早子、晚子选项按文档处理，不能跨错日期。

### 2. 八字与日主人格

- 日主只能取日干，不能取年干、生肖、纳音或五行数量最多的一项。
- 十日主和国风称号完全按设计表映射；标签和称号由程序确定。
- 八字年以立春交接时刻、月以“节”交接时刻确定。
- 使用 EightChar sect=2 的日柱口径；起运单独使用 getYun(gender, 2)，两个 sect 不是同一个配置含义。
- 起运与交运按实际时间区间计算，不仅比较年份。未起运阶段不能作为第一步正式大运。
- 当前流年不直接等于公历年份。流年区间为立春到下一立春；一年内交运时分段解读。
- 未知时辰时只能输出已确定的事实和允许的简版内容，不编造完整时柱和唯一大运。

### 3. 太阳星座

- 采用地心热带黄道十二星座，不扩展月亮、上升、宫位和恒星黄道。
- 禁止通过固定“某月某日到某月某日”的表判断星座。
- 禁止把 lunar 的 Solar.getXingZuo()/getXingzuo() 当作最终算法：它按固定月日划分。
- 复用已独立校验的当年中气交接时刻，建立 UTC 入宫事件，按 `[start, nextStart)` 匹配。对应表见设计文档。
- 边界数据包含相邻年份，处理跨年和节气名称别名。
- 输入范围跨交界时返回候选，不随机取其中一个，不输出“双星座人格”或无依据概率。
- 天文引擎的边界缓冲与生日输入精度分别记录。精度验证不通过时不得宣称精确到分钟或秒。
- 相同 UTC 瞬间以不同时区输入时，星座必须一致。

## 四、系统实现方式

采用两个 POST 接口：

1. `/api/chart`：输入校验和确定性计算，以普通 JSON 先返回人格基础卡、星座和排盘事实。
2. `/api/reading`：接收原始出生输入，在服务端重新计算事实后调用模型，以 SSE 返回实时思考与最终校验结果。不要相信客户端提供的排盘结果。

这两个接口共用同一组日期和排盘函数。API 请求与响应合同以设计文档为准。使用受限的 `asOfUtc` 对齐同轮计算，使用 `chartFingerprint` 和客户端请求序号避免旧响应覆盖新输入。

模型只返回文字解读 JSON。排盘事实、标签、称号、星座、年份和交接时刻由服务端保有。按随附提示词校验字段、长度、事实依据、允许模块和年份。无合法输出就失败，不强行渲染模型返回的任意 HTML 或半段 JSON。

首版不需要数据库、登录系统、Redis、任务队列、向量库、RAG、Agent 框架、微服务或多层抽象。进程内限流仅适用于单实例，README 必须写明多实例时的替换条件。复用已有依赖，不为几个简单函数引入大型框架。

用户已指定 DeepSeek 官方 DeepSeek-V4.1-Flash，并要求最高思考档位。必须落实下面的请求配置：

```json
{
  "model": "deepseek-flash",
  "thinking": { "type": "enabled" },
  "reasoning_effort": "max",
  "response_format": { "type": "json_object" },
  "max_tokens": 131072,
  "stream": true,
  "stream_options": { "include_usage": true }
}
```

官方请求地址为 `https://api.deepseek.com/chat/completions`；密钥只从服务端 `DEEPSEEK_API_KEY` 环境变量读取。项目的 `.env.local` 是私有配置，保留但不要读取到输出、复制进提示词或提交。转交到新环境时由用户在部署平台注入密钥；`.env.example` 只提供变量名。严禁前端 `NEXT_PUBLIC_` 密钥或第三方中转。

注意 API ID 为 `deepseek-flash`，不能照产品名臆造 `deepseek-v4.1-flash`。`max` 是最高思考档位，默认 `high` 不满足用户要求；重试也必须维持 max。开发期按文档核对该服务别名对应的版本，不能未经用户同意换模型。

使用原生服务端 HTTP 请求即可，不需要为了兼容格式增加 Agent 框架。思考模式下不靠降低 temperature 控制稳定性。官方 JSON Output 使用 `json_object`；Schema 在提示词中约束、在本地严格校验，不要传不支持的 `json_schema` 响应格式。

必须实现真实流式输出：

- 分别处理 `choices[0].delta.reasoning_content` 与 `delta.content`，二者可能同时存在。思考转发为 thinking_delta；正文只在服务端累积，正常结束且通过全部校验后一次发送 result，不能向用户展示半段 JSON。
- 浏览器通过 `fetch(POST)` 读取 SSE；不使用只能 GET 的原生 EventSource，不把生日塞入 URL。事件字段、顺序、错误及完成条件严格遵守系统设计第 8.3 节。
- 支持任意分块、跨块中文、空字段、心跳、结束元数据及 `[DONE]`。输出截断、空正文、意外 EOF 必须有明确失败状态；不得把 reasoning_content 当 JSON 解析。
- 限制正文缓冲为 256 KiB，思考在前端仅保留最近 6000 个 Unicode 字符。取消／断开传播到上游 AbortController；统一清理计时器、连接与进行中标记。
- 使用 no-store、no-transform 并关闭代理缓冲；通过实际浏览器验证思考片段及时到达，不接受服务器流式但页面最后一次性显示。
- 同会话同 requestId 的进行中重复请求返回 409，不重复调用模型，也不复用已经读取的流。流开始后的错误使用 error 事件；重试用 retry 事件明确分隔，清空旧思考；不做自动断线重连或后台补偿任务。

每轮最多两次调用，包含结构修复；通过 `DEEPSEEK_TIMEOUT_MS=300000` 给整轮设置统一截止时间，重试只使用剩余预算。关闭 SDK 隐式重试，或使用原生 fetch 保持次数可控。鉴权错误、用户取消、总超时和 token 截断不自动重试。部署平台、代理和前端超时必须与此预算匹配；不能为了赶超时擅自降低思考档位。

没有模型密钥时，排盘和人格基础卡仍可运行，明确提示“AI 解读尚未配置”。演示文本必须标记为演示，不能冒充实际模型结果。

## 五、UI 和导出

- 用户只需一次填写，结果在同页出现；手机端优先。
- 页面顺序：人格卡 → 摘要 → 人格解读 → 当前大运 → 流年 → 排盘依据。
- 三个流年一次取得，切换无需反复付费请求模型。
- 人格名称和国风称号不能随着年度切换变化。
- 各模块独立处理不确定状态，例如日主确定但星座待确认时仍可展示人格卡。
- 错误保留表单；AI 失败保留排盘结果并允许重试。
- 生成期间在基础卡下展示“AI 思考中”面板：实时模型文本、总耗时、展开／收起、取消。默认约 4 行，每约 100ms 合并更新，用户向上阅读时不强制滚动；完成后收起。
- 标注“过程内容可能调整，请以最终解读为准”。阶段仅随真实事件变化；无片段时保持等待与计时，不能轮播预写话术假装思考，也不能虚构进度百分比。没有 reasoning_content 时允许直接生成正文。
- 思考文本只作纯文本展示，不运行 HTML；不纳入复制报告、PNG、日志或持久化存储。读屏只播报阶段变化，不逐 token 播报。
- 保存 PNG 默认不包含生日、地点、精确时刻和私人困惑。
- 标题、结果、表单错误、键盘焦点、触控区域和字体都需可访问。
- 人格卡由真实 HTML 组件渲染并导出，不要求在运行时调用图像模型。

## 六、数据保护与运行约束

- 不把出生信息放进 URL、公共日志或默认持久化存储。
- 不将完整生日和精确出生地点发送给解读模型；只发送必要的结构化排盘事实与用户自愿填写的困惑。
- 用户困惑属于不可信数据，即使包含“忽略规则”“重新算成另一个星座”也不能改变系统规则。
- 处理请求体大小、限流、超时、取消、同一进行中请求的去重。
- 模型预算限制与进程内限流分开设置。
- 日志可以包含耗时、错误码和 token 用量，不包含出生信息或完整模型内容。

4. 接入模型流式思考面板、结构化解读、失败重试、取消和不确定性处理。
